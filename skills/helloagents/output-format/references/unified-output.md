## 使用边界

- `~auto/~plan/~exec/~init` 等正式命令完成时使用规范模板。
- 高风险或多步骤交付在固定结构能显著提高可核查性时使用规范模板。
- 普通咨询、自适应路径的中间阶段和简单改动完成不强制使用本模板。

- 无论是否使用模板，写入交付都必须说明结果、关键文件、实际验证和剩余风险。

---

文件较多或存在多个遗留方案时使用纵向清单；只有一两个文件时可在正文内说明。

```
文件清单:
📁 变更:
  - {文件路径1}
  - {文件路径2}
  ...

遗留方案清单:
📦 遗留方案: 检测到 X 个未执行的方案包:
  - {方案包名称1}
  - {方案包名称2}
  ...
可使用 ~exec 选择执行；如确认不再执行，可明确请求标记为取消后归档。

其他清单（已符合规范）:
- 追问问题: 1. {问题}...
- 用户选项: [1] {选项}...
- 失败任务: - [X] {任务}...
```

**模板方法模式:** 正式命令或复杂交付的推荐结构。

**渲染结构：**
```
{状态符号}【HelloAGENTS】- {阶段名称}

[阶段输出: ≤5条结构化要点]

────
📁 变更:
  - {文件路径1}
  - {文件路径2}
  ...

🔄 下一步: [≤2句建议]

[📦 遗留方案: (按 lifecycle Skill 规则显示，如有)]
```

**状态符号映射:**
- ✅ : 阶段成功完成
- ❓ : 等待用户输入/选择
- ⚠️ : 警告/部分失败/需要用户决策
- 🚫 : 操作已取消
- ❌ : 严重错误/路由失败
- 💡 : 咨询问答（技术咨询、概念解释）

**阶段名称:**
- 需求分析、方案构思、方案设计、开发实施
- 微调模式完成、轻量迭代完成
- 全授权命令完成、规划命令完成、执行命令完成、知识库命令完成
- 咨询问答

**遗留方案提醒:**
  触发场景: 方案设计/轻量迭代/开发实施/规划命令/执行命令/全授权命令完成时
  执行规则: 按 lifecycle Skill 扫描并显示
  显示位置: 输出格式末尾的可选插槽

**交互选项插槽:** 阶段总结后需要立即选择时，把选项嵌入同一个主模板的阶段输出区，并在输出前设置对应 `PENDING_INTERACTION`；不得再追加第二个独立主模板。适用于 `MM_REVIEW`、阶段确认和质量风险选择。

**适用范围:** 正式命令或复杂阶段最终完成时的总结输出（不适用于普通咨询、中间进度和静默阶段转换）

**语言规则:** 自然语言遵循用户和项目当前语言约定，标识符与专有名词保持原样。
