# 代码分析与输出

## 只读勘察

用户要求现状分析，或需求缺口依赖现有代码事实时:

- 允许读取知识库和相关代码，搜索模块、接口、配置、测试和既有行为。
- 不进入方案设计，不创建方案包，不修改代码、测试、配置或知识库。
- 勘察事实用于补齐可查证信息，不当作用户已确认的需求。

## 目标、成功标准与验证策略

- 从需求中提炼关键目标和可验证的成功标准；成功标准无法从需求和代码确定、且影响实现或验收时才追问。
- 判定 TDD 适用性（强制 / 建议 / 例外 / 不确定）；涉及新功能、Bug 修复、行为变更或核心逻辑调整时读取 `tdd`。
- 遗留代码、无测试框架或环境不可稳定复现时，提前确定验证方式：自动化测试、手工验证或 TDD-EXEMPT。

## 代码分析

- 按模块边界、公共契约和依赖评估影响范围，不按文件数决定处理深度。
- 定位相关模块，标记与本次目标相关的过时信息、安全风险和明显缺陷。
- 有日志或错误信息时一并分析。
- 涉及项目未使用过的库或重大版本升级时，查询最新文档后再下结论。

## 输出与后续

- **只读请求:** 直接回答需求、成功标准、关键风险和证据，然后结束；不自动进入设计。
- **仍有阻塞性缺口:** 说明缺口并等待决定，同时继续不依赖答案的调查。
- **已有改动授权（低/中风险）:** 分析结果作为内部上下文，连续进入必要的设计或开发，不输出阶段总结，不再次确认。风险升级为高时停止并确认。
- **`~auto` / `~plan`:** 连续进入方案设计，在命令终点统一总结。
