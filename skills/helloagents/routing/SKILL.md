# 路由

**目标:** 把用户消息映射到命令、上下文响应、系统化调试、改动或咨询问答，并选择成本与风险相称的处理深度。

---

## 判定顺序

1. 命令: `~auto` / `~helloauto` / `~fa` / `~plan` / `~design` / `~exec` / `~run` / `~execute` / `~test` / `~init` / `~wiki`。
2. 上下文响应: 当前正在等待的追问、选择或确认，或对进行中任务的补充与修改。
3. 系统化调试: Bug、测试/构建失败、运行异常、性能回退、flaky 或超时。
4. 改动请求: 判断写入授权，再按低/中/高风险选择路径。
5. 咨询问答: 解释、审查、比较或只读分析。

## 正反例

**应触发:**
- 用户输入特殊命令。
- 请求的风险等级或授权边界不清，例如跨模块改动但契约影响未知。
- 进行中任务收到新输入，无法确定是补充还是新需求。

**不应触发:**
- 简单事实问答，或风险明显为低的明确改动请求。
- 已在实施中执行具体编辑时重复路由。

---

## 完成门禁

- 意图已判定，只读请求没有被推断出写入授权。
- 风险等级及触发它的具体因子已明确；命中多个等级时取最高。
- 处理路径唯一；存在影响正确性或授权的关键分歧时已说明并澄清。
