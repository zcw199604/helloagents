### plan/ 和 history/ 下的 task.md

**Markdown anchor链接格式按why.md实际章节标题生成**

**任务元数据要求:** 每个可执行任务必须包含 `执行模式`、`涉及文件`、`完成标准`、`验证方式`。`执行模式` 可选:
- `AFK`: 可由代理自主完成，无需用户中途输入。
- `HITL`: 需要用户确认、凭据、外部环境、高风险授权或人工验收。

```markdown
# 任务清单: [功能名称]

目录: `helloagents/<branch-name>/plan/YYYYMMDDHHMM_<feature>/`

---

## 并行子代理标注（可选）

启用条件: 仅当任务组独立、无顺序依赖、写入范围不重叠且验证方式明确时保留本节。

- 并行组 A: 任务 [1.1, 4.1]；允许写入: `path/to/a.ts`, `wiki/modules/a.md`；冲突域: 无；验证: `[验证命令]`
- 并行组 B: 任务 [2.1]；允许写入: `path/to/b.ts`；冲突域: 无；验证: `[验证命令]`
- 不可并行任务: [3.1, 5A.4]；原因: 安全检查/最终验证需在集成后执行

---

## 0. 方案边界确认
- [ ] 0.1 确认本次任务仅覆盖 why.md 的范围内切片，范围外内容不进入实现
  - 执行模式: AFK
  - 涉及文件: `why.md`, `how.md`, `task.md`
  - 完成标准: 范围内/范围外边界一致且无互相矛盾描述
  - 验证方式: 只读核对方案包三件套
- [ ] 0.2 确认 how.md 的设计边界完整，尤其是模块职责、接口契约、数据边界和依赖边界
  - 执行模式: AFK
  - 涉及文件: `how.md`
  - 完成标准: 每个受影响模块均有明确边界说明
  - 验证方式: 只读核对 how.md 设计边界
- [ ] 0.3 大型项目确认最小改动策略: 不做无关重构、目录搬迁、依赖升级或公共API重命名
  - 执行模式: AFK
  - 涉及文件: `how.md`, `task.md`
  - 完成标准: 非必要扩大项已列入范围外或后续计划
  - 验证方式: 只读核对任务清单和设计边界

## 5. 测试

### 5A. TDD路径（适用时保留）
- [ ] 5A.1 RED: 按项目现有测试结构选择最小合适层级，为 [可观察行为] 添加失败测试，确认失败原因是 [预期原因]
  - 执行模式: AFK
  - 涉及文件: [测试文件]
  - 完成标准: 测试失败且失败原因匹配目标行为
  - 验证方式: [测试命令]
- [ ] 5A.2 GREEN: 以最小生产实现让 RED 测试通过，依赖任务5A.1
  - 执行模式: AFK
  - 涉及文件: [生产文件]
  - 完成标准: RED 测试通过且未扩大范围
  - 验证方式: [测试命令]
- [ ] 5A.3 REFACTOR: 在测试保持通过的前提下整理实现，依赖任务5A.2
  - 执行模式: AFK
  - 涉及文件: [生产文件/测试文件]
  - 完成标准: 行为不变，相关测试仍通过
  - 验证方式: [测试命令]
- [ ] 5A.4 VERIFY: 运行 [测试命令]，记录相关测试结果，依赖任务5A.3
  - 执行模式: AFK
  - 涉及文件: [测试文件/生产文件]
  - 完成标准: 验证命令已运行且结果摘要可复核
  - 验证方式: [测试命令]

### 5B. TDD-EXEMPT路径（不适用TDD时保留）
- [ ] 5B.1 TDD-EXEMPT: [例外任务]，原因: [纯文档/无行为变化/无测试框架/用户约束/其他]；替代验证: [手工验证/现有测试/代码审查/其他]
  - 执行模式: AFK
  - 涉及文件: [受影响文件]
  - 完成标准: 例外原因和替代验证均已记录
  - 验证方式: [替代验证方式]
  - 证据记录: 开发实施步骤7.5在 schema v3 `qa-review.json.tdd` 中记录 `decision=exempt`、原因和替代验证
```

**任务状态符号:** 遵循 lifecycle Skill 的 G11 定义

**QA 证据说明:** `qa-review.json` 由开发实施步骤7.5在任务执行和测试完成后生成。新记录使用 schema v3，并在 `tdd` 中保存 RED/GREEN/REFACTOR/VERIFY 或 TDD-EXEMPT 证据；该文件不作为单个 `task.md` 任务的完成标准，避免任务验证与 QA 证据互相依赖。

### 轻量迭代 task.md

轻量方案包只省略独立的 `why.md` / `how.md` 文件，不省略范围、场景、知识库和验证信息。

```markdown
# 任务清单: [功能名称]

模式: 轻量迭代

## 轻量方案包元数据
- **范围摘要:** [本次修改覆盖什么、不覆盖什么]
- **核心场景:** [可观察行为或明确写“无行为变化”]
- **知识库同步:** [受影响模块/API/数据/架构/术语；无则写“无”]
- **ADR:** [无 / 决策摘要]
- **验证策略:** [TDD RED-GREEN-REFACTOR-VERIFY，并写入 schema v3 `qa-review.json.tdd` / TDD-EXEMPT 原因和替代验证]

## 任务
- [ ] 1.1 [具体任务]
  - 执行模式: AFK
  - 涉及文件: [文件]
  - 完成标准: [可独立判定的布尔条件]
  - 验证方式: [命令或人工步骤]

## 安全与验证
- [ ] 2.1 执行安全检查和目标验证
  - 执行模式: AFK
  - 涉及文件: [本次改动文件]
  - 完成标准: 无新增安全问题且验证结果可复核
  - 验证方式: [安全审计命令]；[测试命令]
```
