# 交互询问输出格式

需要用户选择或确认时使用。输出时按 `lifecycle` 记录等待项。

```
❓【HelloAGENTS】- {场景名称}

[情况说明，≤3 句]

[1] {选项1} - {说明}
[2] {选项2} - {说明}

────
🔄 下一步: {引导文字}
```

约束:

- 选项 2-4 个，每个说明不超过一句；推荐项标注“推荐”。
- 只有“是/否”两种结果时可以省略编号，直接问“是否……? (是/取消)”。
- 开放式追问（需求缺口）不列选项：先说明缺口及影响，再提出最少必要的问题。
- 输入无效时重复原问题和选项，不改变等待项。
- 警告性质的选择（风险接受、部分失败）把 ❓ 换成 ⚠️。

常见场景名称: 需求分析（追问）、方案构思（方案选择）、方案确认（是否执行）、开发实施（方案包选择）、QA 风险决策、上下文确认、命令确认（仅覆盖已有知识库时）、多模型审查。各场景的选项由对应 Skill 给出。
