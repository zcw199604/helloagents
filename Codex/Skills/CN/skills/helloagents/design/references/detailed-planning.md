# 详细规划

每次创建新的方案包，使用当前时间戳，不复用 `plan/` 中的遗留方案。

## 1. 创建方案包

- 目录和同名冲突处理见 `lifecycle`；创建后记为 `CURRENT_PACKAGE`。
- 读取 `templates` 获取模板。高风险或存在架构取舍时生成完整方案包 `why.md`、`how.md`、`task.md`；其余情况可生成仅含 `task.md` 的轻量方案包。
- 方案涉及项目未使用过的库、框架或重大版本升级时，先查询最新文档，结论写入 `how.md` 的技术方案。

## 2. 任务清单规则

```yaml
任务元数据:
  - 每个任务标明 执行模式、涉及文件、完成标准、验证方式 和依赖关系
  - AFK 表示可自主执行；HITL 表示需要用户确认、凭据、外部环境或高风险授权
  - 完成标准是可由另一个代理只读核对的布尔条件，不写"优化完成""适当调整"
任务粒度:
  - 每个任务能在一个独立的测试周期内完成和验证
  - 限定在直接相关模块和最小文件集合
  - 风格整理、目录搬迁、依赖升级、公共接口重命名不混入功能任务；确需重构时拆为独立任务并说明必要性、回滚方式和验证命令
设计边界:
  - how.md 明确范围内/范围外、模块职责、接口契约、数据边界和依赖边界
验证规模适配:
  - 常规项目规划覆盖核心路径、受影响契约和高风险回归的最小充分验证，不为覆盖率数字或假设性风险扩展范围
  - 大型、复杂、高故障成本或公共契约影响广的项目，可基于风险增加测试层级、覆盖范围和审查深度，并在 how.md 或 task.md 记录依据
  - 缩减验证范围不得降低安全、公共契约和核心行为门禁
TDD:
  - 对强制/建议启用 TDD 的可测试行为读取 tdd，拆为 RED → GREEN → REFACTOR → VERIFY，测试任务排在实现任务之前
  - 例外任务标注 TDD-EXEMPT 和原因
安全检查:
  - 包含一项覆盖本次改动的安全检查任务
并行子代理:
  - 存在可并行任务组时按 hello-subagent 的触发条件标注并行组、允许写入范围、冲突域和验证命令
  - 文件边界或依赖关系不清晰时不标注
```

## 3. 领域语言

需求分析输出了领域语言候选，或方案引入新的业务概念、角色、状态、流程名或命名约定时:

- 按 `kb` 的领域语言维护规则，在 `why.md` 核心场景中使用已确认术语，在 `how.md` 记录待写入 `wiki/glossary.md` 的变更，并在 `task.md` 增加对应的知识库同步任务。
- 待确认术语不得强制用于代码命名；同一概念只保留一个推荐名称，其他叫法记为同义词/禁用叫法。

## 4. 风险与 ADR

- 为方案构思识别出的实际风险制定规避措施，写入 `how.md` 的安全与性能章节。风险取舍需要用户决定时询问；由 `~auto` 或默认 `~plan` 推进时选择规避风险的做法。EHRB 始终按 `routing` 处理。
- 出现以下取舍时在 `how.md` 记录 ADR 候选（背景、决策、替代方案、影响、状态）：排除了一个实际可行的替代方案；引入或改变模块边界、数据边界、接口契约或依赖方向；采用分阶段迁移、兼容层、适配器或回滚策略；领域语言定义影响代码命名、模块边界或用户可见行为。没有取舍时省略 ADR 章节。

## 5. 自审

方案文件生成后、输出前核对:

- **范围一致:** 需求、技术方案和任务清单覆盖同一需求切片。
- **边界清晰:** 范围内/范围外、模块职责、接口契约、数据和依赖边界无歧义。
- **最小改动:** 不存在无必要的重构、迁移、依赖升级或公共 API 改名。
- **可验证:** 每个核心场景都有对应任务和验证方式；验证深度与规模和风险相称。
- **风险闭环:** EHRB、安全、性能、回滚和兼容性风险已有缓解措施。
- **无占位遗留:** 没有未解释的 TODO/TBD/待定，也没有互相矛盾的描述。

发现问题就修正并核对受影响部分；无法消除影响设计正确性的关键不确定性时，说明缺口并等待决定。
