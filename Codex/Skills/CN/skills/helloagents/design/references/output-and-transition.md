# 方案设计输出与后续处理

设计完成后的去向由授权决定，写入入口以 `develop` 的“入口”为准:

| 情况 | 输出 | 后续 |
|---|---|---|
| `~plan` | 规划命令完成格式 | 清理流程状态并停止，不进入实施 |
| `~auto` | 不输出阶段总结 | 直接进入 `develop` 的方案包流程 |
| 已有改动授权的低/中风险改动（设计仅用于内部拆解或可恢复记录） | 不输出阶段总结 | 直接进入 `develop`；风险升级为高或命中 EHRB 时停止并确认 |
| 其他（高风险，或用户只要求设计） | 方案摘要 | 询问是否按此方案执行并记录等待项 |

等待确认时:

- 明确同意 → 进入 `develop` 的方案包流程。
- 明确拒绝 → 清理流程状态并结束，方案包保留在 `plan/`。
- 提出修改 → 按 `routing` 的上下文响应规则处理。

## 方案摘要

需要对外输出时按 `output-format` 选择格式，只包含实际内容:

- 方案概要和复杂度判定依据。
- 任务清单概要和主要风险（含 EHRB）。
- 方案包文件路径。
- 遗留方案提示（按 `lifecycle` 扫描，排除本次创建的方案包）。

## 多模型审查

只在用户明确要求时执行：读取 `multi_model`，按方案设计阶段规则交叉评审，输出共识项、分歧项和最终建议，之后回到上表的后续处理。未要求时不询问；高风险方案可在摘要末尾用一句话提示可以另行发起审查。
