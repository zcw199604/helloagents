# 输出格式

**目标:** 让输出服务于结果交付，只在结构确实提高可读性或承载交互时使用模板。

---

## 何时使用模板

| 输出场景 | 状态符号 | 读取文件 |
|---|---|---|
| `~auto` / `~plan` / `~exec` / `~init` 命令完成，或方案包交付 | ✅ / ⚠️ | `references/unified-output.md`、`references/command-output.md` |
| 错误、取消、安全警告、部分失败 | ❌ / 🚫 / ⚠️ | `references/exception-output.md` |
| 需要用户选择或确认 | ❓ / ⚠️ | `references/interactive-output.md` |

不使用模板的场景:

- **咨询问答和只读分析:** 直接回答，不加 `【HelloAGENTS】`、阶段名、状态符号或文件变更栏。简单问题一两句；复杂问题先给结论，再用必要的短段落或列表说明证据、假设与限制。
- **低/中风险改动完成:** 用自然段或短列表说明结果、关键文件、实际验证和剩余风险。
- **中间进度、内部分析与设计:** 简短自然语言，或静默连续执行。

---

## 通用约束

- 无论是否使用模板，写入交付都说明结果、关键文件、实际验证和剩余风险。
- 单次用户可见消息只有一个主模板；需要立即选择时把选项嵌入同一个模板。
- 输出询问时按 `lifecycle` 记录等待项。
- 文件较多时才用纵向清单；没有变更时不声明“变更: 无”，没有真实下一步时不添加邀约式建议。
- 交互模板只在本 Skill 定义，其他 Skill 只说明场景名称、情况说明和选项。

---

## 完成门禁

- 使用模板时状态符号与场景匹配，且只有一个主模板。
- 正式交付说明了结果、关键文件、验证结果和剩余风险。
- 询问已记录等待项，选项完整。
