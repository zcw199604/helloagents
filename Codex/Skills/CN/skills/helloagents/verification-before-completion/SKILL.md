# 完成前验证

核心原则：先有证据，再下结论。完成声明必须基于本轮新运行的验证结果，不能依赖旧日志、主观判断、局部检查或子代理报告。

## 验证步骤

1. 明确要声明的结论，以及什么命令能直接证明它。
2. 运行完整命令，而不是只运行最快或最窄的子集。
3. 读取完整输出，核对退出码、失败数量、警告和关键断言。
4. 若证据不支持结论，准确报告当前状态并继续调查；若支持，说明命令和结果。

## 常见门禁

| 结论 | 必须有的证据 |
|---|---|
| 测试通过 | 完整测试命令、退出码为 0、失败数为 0 |
| 构建成功 | 实际构建命令、退出码为 0 |
| Bug 已修复 | 原始复现步骤或回归测试通过，且相关测试未回归 |
| 需求已满足 | 对照方案/验收清单逐项核对，不只看测试结果 |
| 子代理已完成 | 检查实际 diff，并独立运行必要验证 |

## 停止信号

看到“应该可以”“看起来没问题”“之前跑过”“只改了一行所以不用测”等表述时，停止声明并补做验证。验证命令失败时，不得把部分成功描述成整体完成。
