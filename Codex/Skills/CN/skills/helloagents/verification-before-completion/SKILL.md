# 完成前验证

核心原则：先有证据，再下结论。完成声明必须对应实际验证结果，结论范围不得超过证据覆盖范围。

## 证据有效性

- 核对证据对应的代码版本或变更状态、依赖、环境、命令和结果；这些条件未变化，且覆盖当前结论时，可以复用同一任务已有证据。
- 上下文压缩、会话恢复或代理切换本身不使证据失效。代码、依赖或相关环境变化，出现新的故障信号，证据缺失或用户要求重新验证时，只重跑受影响范围。
- 测试失败不得被旧的成功日志覆盖；用户明确要求全量测试或项目要求完整构建时，必须满足该范围。

## 验证步骤

1. 明确要声明的结论，以及什么命令能直接证明它。
2. 复用仍有效的对应证据；不足时运行与风险、受影响契约和成功标准相称的验证命令。
3. 核对退出码、失败数量、警告和关键断言；输出截断时补读影响判断的部分。
4. 若证据不支持结论，准确报告当前状态并继续调查；若支持，说明命令和结果。

## 常见门禁

| 结论 | 必须有的证据 |
|---|---|
| 测试通过 | 明确测试范围和命令，退出码为 0、失败数为 0；目标测试通过只能证明该范围 |
| 构建成功 | 实际构建命令、退出码为 0 |
| Bug 已修复 | 原始复现步骤或回归测试通过，且相关测试未回归 |
| 需求已满足 | 对照方案/验收清单逐项核对，不只看测试结果 |
| 子代理已完成 | 主代理检查实际 diff 与验证证据；证据无法核实、集成状态变化或存在覆盖缺口时独立验证 |

无法运行自动化验证时，记录原因、实际替代验证和剩余限制，不把未执行的测试描述为通过。

## 停止信号

看到“应该可以”“看起来没问题”或无法核实的“之前跑过”时，停止声明并核实或补做验证。验证命令失败时，不得把部分成功描述成整体完成。
