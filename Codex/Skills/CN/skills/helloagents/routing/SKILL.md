# 路由机制

**目标:** 将用户消息映射到咨询问答、命令路径、系统化调试、开发模式或上下文响应。主文件保留最小决策流，详细规则按需读取。

---

## 快速决策流

1. 扫描命令词：`~auto` / `~helloauto` / `~fa` / `~plan` / `~design` / `~exec` / `~run` / `~execute` / `~test` / `~init` / `~wiki`。
2. 判断是否为上一阶段的确认、选择或反馈。
3. 判断是否存在 Bug、测试失败、构建失败、运行异常、性能回退或 flaky 信号。
4. 判断是否存在代码/文档改动意图。
5. 判断 EHRB 信号；无法规避时按安全警告暂停。
6. 输出路由后重述；不确定时选择更完整、更安全的流程。

## 正反例

**应触发:**
- 用户输入 `~plan`、`~exec` 或确认方案继续。
- 用户报告“测试失败”“构建失败”“线上接口异常”。
- 用户请求跨文件改动，但范围或风险边界不清。

**不应触发:**
- 简单事实问答且不需要阶段流。
- 已在明确开发实施中执行具体文件编辑时重复路由。

---

## 完成门禁

- 意图类型已判定：问答型、改动型或命令型。
- 改动范围已判定：无、微、小、中、大或不确定。
- 调试信号和 EHRB 信号已显式判定。
- 最终路由唯一；若不唯一，按 G3 输出不确定因素和选项。
