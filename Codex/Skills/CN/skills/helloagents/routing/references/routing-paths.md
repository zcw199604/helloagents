# 处理路径与门禁

## 处理路径

<complexity_paths>

**咨询问答**
- 条件: 不满足以上任何条件（兜底）
- 动作: 按 output-format Skill 的 G6.3 格式直接回答

**系统化调试模式**
- 条件(满足任一): 用户报告Bug、测试失败、构建失败、运行异常、性能回退、flaky/超时、错误日志、stack trace、回归问题
- 动作:
  1. 优先进入开发实施的系统化调试门禁（见 `develop` Skill）；该入口仅允许只读根因调查和复现闭环构建，修复代码前仍必须创建或选择方案包
  2. 修复前必须完成: 读取完整错误、稳定复现、检查近期变更、定位失败层级、追踪坏数据/坏状态来源
  3. 多组件链路必须做边界取证；测试污染问题必须定位 polluter；坏数据类问题根因确认后补必要防线
  4. 每次只验证一个假设；禁止连续叠加未验证补丁
  5. 连续3次修复失败或无法定位根因 → 暂停扩大改动，重新进入需求分析/方案设计或按 G3 请求确认
  6. 根因明确后，按影响范围进入轻量迭代/标准开发/完整研发；调试类改动必须产出方案包，**禁止降级到微调模式**；若涉及EHRB则按完整研发处理
- 输出:
  - 需要用户补充复现信息时: 按需求分析追问格式
  - 已完成修复时: 按最终实际开发模式输出（轻量迭代/开发实施/命令完成），方案包路径必须出现在变更清单中

**微调模式**
- 条件(全部满足): 意图=改动型, 指令明确含文件路径, 文件≤2, 行数≤30, 无架构影响, 命令修饰=无, EHRB=无, **调试信号=无**
- 动作: 直接修改代码
- 知识库处理:
  - 知识库不存在: 不创建，在输出中提示"建议执行 ~init"
  - 知识库存在:
    - 快速检查核心文件存在性（CHANGELOG.md, project.md, wiki/*.md）
    - 核心文件缺失 → 跳过知识库更新，在输出中提示"建议执行 ~init 修复"
    - 核心文件完整 → 仅更新受影响模块的 `wiki/modules/<module>.md`（如有对应模块文档）
- EHRB门槛: 检测到EHRB信号 → 输出风险升级提示，按目标模式执行
- 输出格式:
  ```
  ✅【HelloAGENTS】- 微调模式完成

  - ✅ 改动: [修改内容简述]
  - 📁 涉及文件: [文件名称]
  - 📚 知识库: [已更新/⚠️建议执行 ~init]

  ────
  📁 变更:
    - {文件路径1}
    - {文件路径2}
    ...

  🔄 下一步: 请验证改动效果
  ```

**轻量迭代**
- 条件(全部满足): 意图=改动型, 指令明确, 文件3-5, 无架构决策, 命令修饰=无, EHRB=无
- 动作流程:
  1. 检查知识库状态并处理（按 G10 快速决策树）
  2. 获取项目上下文（按 G10 快速流程）
  3. 创建简化方案包（仅 task.md，省略 why.md/how.md）
  4. 执行代码改动
  5. 同步更新知识库（按 `kb` Skill 同步规则）
  6. 迁移方案包至 helloagents/<branch-name>/history/
  7. 扫描遗留方案
- 简化方案包规则:
  - 路径: `helloagents/<branch-name>/plan/YYYYMMDDHHMM_<feature>/`
  - 仅创建 `task.md`，包含任务清单
  - 迁移时标注"轻量迭代"
- 输出格式:
  ```
  ✅【HelloAGENTS】- 轻量迭代完成

  - ✅ 执行结果: 任务X/Y完成
  - 📦 方案包: 已迁移至 helloagents/<branch-name>/history/YYYY-MM/...
  - 📚 知识库: [已更新/已创建]

  ────
  📁 变更:
    - {代码文件}
    - {知识库文件}
    - helloagents/<branch-name>/CHANGELOG.md
    - helloagents/<branch-name>/history/index.md
    ...

  🔄 下一步: 请验证功能
  [📦 遗留方案: 检测到X个，是否迁移?]
  ```

**标准开发**
- 条件(全部满足): 意图=改动型, 需求明确, 多文件协调或文件>5, 无架构级决策
- 动作: 轻量需求分析 → 方案设计 → 创建完整方案包
- 轻量需求分析要求:
  - 执行 `analyze` Skill 的需求评分、成功标准、TDD适用性和领域语言候选提取
  - 可跳过深度代码扫描，但不得跳过需求完整性评分
  - 评分<7分时必须追问，不能直接进入方案设计
- 阶段边界:
  - 交互确认模式: 方案设计完成后必须输出方案包与阶段总结，等待用户明确确认是否进入开发实施
  - 推进模式仅限全授权命令(~auto等): 方案设计完成后才可继续进入开发实施
- 输出: 先复用方案设计阶段输出格式；只有满足开发实施入口硬门禁后，才复用开发实施阶段输出格式

**完整研发（默认兜底）**
- 条件(满足任一): 需求模糊, 涉及架构决策, 涉及新模块, 涉及技术选型, 影响范围不确定, EHRB=有
- 动作: 需求分析 → 方案设计 → 创建完整方案包
- 阶段边界:
  - 交互确认模式: 需求分析完成后等待确认进入方案设计；方案设计完成后等待确认进入开发实施
  - 规划命令(~plan等): 执行到方案设计并创建方案包后停止，不进入开发实施
  - 全授权命令(~auto等): 完成方案设计并创建方案包后，才可静默进入开发实施
- 兜底: 无法判断时默认此路径

### 开发实施入口硬门禁

路由阶段不得把普通开发模式、追问响应、方案选择、阶段确认、新需求响应直接解释为开发实施授权。

**只有以下3种情况可以进入开发实施:**
```yaml
1. 已存在当前会话刚创建的完整方案包，且当前用户输入明确确认进入开发实施（允许中间经过多模型审查或确认提示）
2. 全授权命令(~auto/~helloauto/~fa)触发，且已完成方案设计并创建方案包
3. 执行命令(~exec/~run/~execute)触发，且 `helloagents/<branch-name>/plan/` 中存在完整方案包
```

如不满足上述条件，即使路由判定为标准开发或完整研发，也只能推进到方案设计并创建方案包，不能修改业务代码。
