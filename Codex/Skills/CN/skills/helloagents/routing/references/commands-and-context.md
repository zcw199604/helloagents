# 命令与上下文响应

## 命令

用户输入命令即表示授权，直接执行，不再询问“是否执行”。只有以下情况先停下:

- **覆盖已有知识库:** `~init` / `~wiki` 且 `helloagents/<branch-name>/` 下已有知识库文件。说明将被重建的范围并等待确认。
- **EHRB:** 任何命令都不绕过高风险确认。
- **缺少必要对象:** 命令没有带需求、`~test` 的范围无法确定、`~exec` 有多个方案包可选。只问缺的那一项。

| 命令 | 触发词 | 行为 | 终点 |
|---|---|---|---|
| 全授权 | `~auto` / `~helloauto` / `~fa` | 需求分析 → 方案设计 → 开发实施连续执行，中间不输出阶段总结 | 方案包归档并总结 |
| 规划 | `~plan` / `~design` | 需求分析 → 方案设计，创建方案包 | 方案包创建后停止，不修改业务代码 |
| 执行 | `~exec` / `~run` / `~execute` | 执行 `plan/` 中的合法完整或轻量方案包 | 方案包归档并总结 |
| 测试 | `~test [scope]` | 读取 `test`，为指定范围补测试 | 测试与验证摘要 |
| 知识库 | `~init` / `~wiki` | 读取 `kb`，初始化或重建知识库 | 知识库文件与总结 |

各命令细则:

- **`~auto`:** 设置 `ACTIVE_COMMAND=auto`。高风险或存在架构取舍时创建完整方案包，其余使用轻量方案包；方案取舍自动采用推荐方案。之后按 `develop` 的方案包流程执行。
- **`~plan`:** 设置 `ACTIVE_COMMAND=plan`。默认自动采用推荐方案并创建方案包；用户在命令中要求比较方案或自己选择时，在方案构思处输出对比并等待选择。只写入方案包和必要的知识库文件。
- **`~exec`:** 设置 `ACTIVE_COMMAND=exec`，按 `develop` 的方案包流程（`plan-package-flow.md`）确定方案包。`plan/` 为空时说明原因并提示先用 `~plan`。
- **`~test`:** 不设置命令授权，按改动授权处理，写入范围限于测试；详见 `test`。
- **`~init` / `~wiki`:** 不设置命令授权；知识库不存在时直接创建。

命令结束（成功、取消、终止或出错）时按 `lifecycle` 清理流程状态。用户取消时简短说明已取消；原始输入带有具体需求时，可说明仍可按普通请求处理。

## 上下文响应

以 `lifecycle` 的 `PENDING` 为准，不从上一条文本猜测状态。

- **回答等待项:** 回复对应正在等待的问题时消费一次并清除。回复与问题不对应时不套用序号或“是/否”。
- **确认的范围:** 确认只对被问的那一件事有效。同意方案不等于同意方案之外的改动；确认风险只覆盖已说明的风险。
- **补充信息:** 补充边界、范围或成功标准不增加写入授权，也不取消原有授权。缺口消除后按原有授权继续，不再重复确认。
- **修改意见:** 改变目标、范围或验收标准的重大变更，说明后回到需求分析；局部调整在当前阶段直接应用。
- **新需求:** 用户明确取消、替换当前目标或提出不兼容的新任务时，清理流程状态后重新路由。

打断规则:

- 命令可以打断进行中的任务，先清理旧的流程状态。
- 同一任务的补充、纠正或状态询问保留原目标与授权；“另外/还有”本身不构成重置依据。
- 无法判断新输入是补充还是新任务时，询问用户选择“继续当前任务”或“开始新任务”，并各附一句简述。
