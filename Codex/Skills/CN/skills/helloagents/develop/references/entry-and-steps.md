# 开发实施入口与执行步骤

## 强制前置检查

<p3_entry_gate>
**说明：** 即使路由判定进入开发实施，此检查仍会验证合法性（双重保险）

**开发实施的唯一合法条件（满足任一即可）：**

```yaml
条件A - 方案设计完成后确认:
  验证方法: 当前会话存在刚创建且完整的方案包(CREATED_PACKAGE或等价状态) 且 当前用户输入为明确确认
  说明: 允许方案设计完成后经过多模型审查、跳过审查提示或"是否进入开发实施"确认提示

条件B - 全授权命令:
  验证方法: MODE_FULL_AUTH状态=true

条件C - 执行命令:
  验证方法: MODE_EXECUTION状态=true

条件D - 系统化调试只读入口:
  验证方法: 路由命中系统化调试模式 且 尚未修改生产代码
  权限: 仅允许执行步骤4.6的根因调查、复现、最小验证和方案判断；修复代码前必须回到方案设计创建完整方案包，或通过条件A/B/C进入开发实施
```

**验证失败处理：**
```
IF 不满足任何条件:
  输出: "❌ 路由错误: 进入开发实施需满足前置条件。当前条件不满足，已重新路由。"
  执行: 将当前用户消息按路由优先级重新判定
  终止: 开发实施流程
```
</p3_entry_gate>

## 执行步骤

**重要:** 所有文件操作遵循G5静默执行规范

### 步骤1: 确定待执行方案包

```yaml
全授权命令(MODE_FULL_AUTH=true):
  - 读取CREATED_PACKAGE变量（方案设计阶段设置的方案包路径）
  - 检查该方案包是否存在且完整
    - 存在且完整 → 使用该方案包，设置CURRENT_PACKAGE = CREATED_PACKAGE
    - 不存在或不完整 → 按 output-format Skill 的 G6.2 错误格式输出并停止
  - 忽略 `helloagents/<branch-name>/plan/` 中的其他遗留方案包

交互确认模式/执行命令(MODE_EXECUTION=true):
  - 扫描 `helloagents/<branch-name>/plan/` 目录下所有方案包
  - 不存在方案包 → 按 output-format Skill 的 G6.2 错误格式输出并停止
  - 方案包不完整 → 按 output-format Skill 的 G6.2 错误格式输出并停止
  - 单个完整方案包 → 设置CURRENT_PACKAGE，继续执行
  - 多个方案包 → 列出清单，等待用户选择
    - 用户输入有效序号(1-N) → 设置CURRENT_PACKAGE，继续执行
    - 用户输入取消/拒绝 → 按 output-format Skill 的 G6.2 取消格式输出，流程终止
    - 无效输入 → 再次询问

异常输出示例:
  方案包不存在:
    ```
    ❌【HelloAGENTS】- 执行错误

    错误: 未找到可执行的方案包
    - 原因: `helloagents/<branch-name>/plan/` 目录为空或不存在

    ────
    🔄 下一步: 请先使用 ~plan 命令创建方案，或进入方案设计阶段
    ```

  方案包不完整:
    ```
    ❌【HelloAGENTS】- 执行错误

    错误: 方案包不完整
    - 方案包: [方案包名称]
    - 缺失文件: [why.md/how.md/task.md]

    ────
    🔄 下一步: 请补充缺失文件或重新创建方案包
    ```
```

### 步骤2: 检查知识库状态并处理

执行方式:
- 按 G10 快速决策树判定
- 如需创建/重建知识库 → 读取 `kb` Skill执行完整流程

### 步骤3: 读取知识库并获取项目上下文

执行方式:
- 按 G10 快速流程执行（先检查知识库 → 不足则扫描代码库）
- 如需详细规则 → 读取 `kb` Skill

### 步骤4: 读取当前方案包

读取 `helloagents/<branch-name>/plan/YYYYMMDDHHMM_<feature>/task.md`、`why.md` 和 `how.md`。

读取目的:
- `why.md`: 确认需求、范围、核心场景和风险。
- `how.md`: 确认技术方案、ADR、接口/数据/依赖边界、测试与部署约束。
- `task.md`: 确认执行任务、依赖顺序和验证命令。

### 步骤4.5: 并行子代理适配判断（可选）

当 `task.md` 中存在多个独立、边界清晰、可验证且无文件写入重叠的任务组时，读取 `hello-subagent` Skill，按其规则进行子任务派发、上下文裁剪、冲突控制和结果验收。

不满足子代理触发条件时，由主代理按后续步骤顺序执行任务。

### 步骤4.6: 系统化调试门禁（适用时）

<systematic_debugging_gate>
**触发条件（满足任一）:**
```yaml
- 用户报告 Bug、测试失败、构建失败、运行异常、性能回退、flaky/超时、回归问题
- task.md 中任务类型为缺陷修复、失败测试修复、构建修复、稳定性修复
- 开发实施过程中出现新的阻断性测试失败或复现异常
```

**根因调查要求（修复前必须完成）:**
- 读取完整错误、日志、stack trace、失败测试名和触发命令，禁止只看最后一行错误
- 稳定复现问题；如无法复现，记录环境、步骤、输入、频率和已排除因素
- 检查近期变更、依赖/配置/环境差异，定位失败是输入、状态、边界条件、并发时序、集成契约还是环境问题
- 多组件链路（如 CI→构建→签名、API→服务→数据库、前端→网关→后端）必须在每个边界记录输入、输出、环境/配置传播和责任层，先证明问题在哪一层产生
- 从报错点沿调用链/数据流向上追踪坏数据或坏状态的来源，优先从源头修复，禁止只在深层报错点做症状补丁
- 测试单跑通过但整套失败，或发现脏文件、数据库记录、缓存、全局变量、时间/随机种子污染时，必须定位污染源测试；优先用二分、最小测试组合或顺序复现找 polluter，禁止只在失败测试里清理结果
- 每轮只提出一个根因假设，并用最小验证手段确认或否定；验证失败后回到调查，不叠加猜测性补丁
- 异步或 flaky 问题优先等待真实条件（状态、事件、DOM、端口、文件、队列为空等），禁止用固定 sleep 猜时间；只有验证真实时间语义时才允许固定等待并记录原因
- 允许临时诊断日志/断言，但必须在提交最终实现前删除或转为项目认可的可观测性代码

**根因确认后的修复规则:**
- 坏数据/坏状态类问题必须优先修复源头，并按需要补入口校验、业务不变量、边界兼容和诊断观测防线
- 防线只覆盖本次根因和可绕过路径，仍遵守大型项目最小改动约束，禁止扩成全面重构
- 时间压力、权威压力、连续失败后的沉没成本都不能跳过根因调查；如证据不足，必须暂停并按G3处理

**停止扩大规则:**
- 连续3次修复尝试失败、根因仍不明确、或修复需要扩大到架构/公共契约时，停止继续改代码
- 按G3输出不确定因素，或将问题重新拆为方案设计任务，不允许继续盲目重构
</systematic_debugging_gate>

### 步骤5: 按任务清单执行代码改动

```yaml
执行规则:
  - 严格按 task.md 逐项执行
  - 如触发系统化调试门禁，先完成根因调查和单假设验证，再修改生产代码
  - 如启用并行子代理，必须由主代理先按 hello-subagent Skill 完成派发前检查、文件边界声明和返回格式约束
  - 子代理结果只作为中间材料，主代理必须复核 changed_files、验证结果和 task.md 状态后再进入后续质量检查
  - 如任务命中TDD适用性（新功能、Bug修复、行为变更、核心逻辑调整或测试策略设计），先读取 `tdd` Skill
  - 默认先完成对应RED任务，再修改生产代码
  - 受遗留代码、无测试框架、环境不可复现或用户约束限制时，必须记录约束、替代验证方式和 TDD-EXEMPT 原因，再按既有验证策略执行

任务成功处理:
  - 每个任务执行成功后，立即将状态从 [ ] 更新为 [√]

任务跳过处理(状态更新为 [-]):
  - 任务依赖的前置任务失败
  - 任务条件不满足
  - 任务已被其他任务的实现覆盖

任务失败处理(状态更新为 [X]):
  - 记录错误信息（用于迁移前添加备注）
  - 继续执行后续任务
  - 所有任务完成后，如存在失败:
    - 交互确认模式/执行命令: 列出失败清单，询问用户决定
      - 用户选择继续 → 继续后续步骤
      - 用户选择终止 → 输出"已终止开发实施"，流程终止
    - 全授权命令: 在总结中列出失败任务，清除MODE_FULL_AUTH状态

代码编辑技巧:
  - 大文件处理(≥2000行): Grep定位 → Read(offset,limit) → Edit精确修改
  - 每次Edit只修改单个函数/类
```

### 步骤5.5: 大型项目最小改动执行约束

<large_project_minimal_change>
**触发条件:** 项目规模判定为大型项目，或任务影响公共模块/跨模块契约

**执行约束:**
- 优先做满足当前方案包成功标准的最小代码改动，避免顺手重构
- 默认不做目录搬迁、批量重命名、公共API改签名、依赖升级、格式化全文件等非必要改动
- 优先保持现有架构、命名、错误处理、日志、测试风格和兼容行为
- 如发现需要大范围重构才能继续，停止扩大改动，将其记录为独立后续方案或按G3请求确认
- 修复缺陷时优先定位根因和最小补丁，避免用整体重写掩盖问题
- 验证范围应覆盖本次触达路径和受影响契约，不因改动小而跳过测试/审计
</large_project_minimal_change>

### 步骤7: 质量检查与测试

```yaml
测试执行: 运行task.md中定义的测试任务，或项目已有测试套件

TDD门禁（适用时严格执行）:
  - RED: 测试必须先失败，且失败原因匹配目标行为
  - GREEN: 仅做最小实现让相关测试通过
  - REFACTOR: 仅在测试通过后重构，重构后必须复测
  - 反模式检查: 不测试mock自身行为、不添加test-only生产接口、复杂mock优先转fake/真实组件/集成测试

测试失败处理规则（严格执行）:
  ⛔ 阻断性测试（核心功能）:
    - 失败必须立即停止执行
    - 输出关键错误格式
    - 等待用户明确决策（修复/跳过/终止）
    - 禁止自动跳过
    - 全授权命令和执行命令也必须停止；不得把阻断性失败仅写入总结后正常结束

  ⚠️ 警告性测试（重要功能）:
    - 失败时在总结中标注
    - 继续执行后续步骤

  ℹ️ 信息性测试（次要功能）:
    - 失败时在总结中记录
    - 继续执行后续步骤
```

**⛔阻断性测试失败输出格式:**
```
❌【HelloAGENTS】- 阻断性测试失败

⛔ 核心功能测试失败，必须处理后才能继续:
- 失败测试: [测试名称]
- 错误信息: [错误摘要]

[1] 修复后重试 - 尝试修复问题后重新测试
[2] 跳过继续 - 风险自负，忽略此错误继续执行
[3] 终止执行 - 停止开发实施

🔄 下一步: 请输入序号选择
```

### 步骤10: 一致性审计

<consistency_audit>
**审计时机:** P3阶段完成知识库操作后立即执行

**审计内容:**
1. **完整性**: 文档涵盖所有模块，必备文件和图表齐全
2. **一致性**: API/数据模型与代码一致，无遗漏、重复、死链

**真实性优先级（冲突解决机制）:**
```
1. 代码是执行真实性的唯一来源 (Ground Truth)
   → 运行时行为、API签名、数据结构以代码为准

2. 默认修正方向: 修正知识库以符合代码
   → 发现不一致时，必须更新文档以反映代码的客观事实

3. 例外（修正代码）:
   - 知识库是最近P2/P3方案包（刚设计好的方案）
   - 代码有明显错误（Bug）
   - 错误信息指向代码问题

4. 存疑时: 双向验证，优先信任最近的代码变更
```
</consistency_audit>

### 步骤12: 迁移已执行方案包至 `helloagents/<branch-name>/history/`

<plan_migration>

⚠️ **CRITICAL - 强制执行规则:**

**不可跳过:** 此步骤为本阶段结束的原子性操作

**执行规则:**

1. 更新task.md任务状态和备注:
   - 所有任务更新为实际执行结果（[√]/[X]/[-]/[?]）
   - 非[√]状态任务下方添加备注（格式: `> 备注: [原因]`）
   - 如有多个失败/跳过任务，可在末尾添加执行总结章节

2. 迁移至历史记录目录:
   - 将方案包目录从 `helloagents/<branch-name>/plan/` 移动到 `helloagents/<branch-name>/history/YYYY-MM/` 下
   - YYYY-MM 从方案包目录名提取（如 202511201200_xxx → 2025-11）
   - 迁移后完整路径: `helloagents/<branch-name>/history/YYYY-MM/YYYYMMDDHHMM_<feature>/`
   - 迁移操作会自动删除 `helloagents/<branch-name>/plan/` 下的源目录
   - 同名冲突处理: 强制覆盖 `helloagents/<branch-name>/history/` 中的旧方案包

3. 更新历史记录索引: `helloagents/<branch-name>/history/index.md`

**警告:** 此操作将导致 `helloagents/<branch-name>/plan/` 下的源文件路径失效，请确保步骤8已完成内容读取
**不可跳过:** 此步骤为本阶段结束的原子性操作
</plan_migration>
