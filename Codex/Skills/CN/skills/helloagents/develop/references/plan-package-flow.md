# 方案包执行流程

存在方案包时，在 `develop` 默认流程之上增加以下环节。调试、TDD、最小充分实现、安全检查和验证要求与默认流程相同，本文件不重复。

## 1. 确定方案包

- `~auto` 或设计后确认: 使用本次设计刚创建的方案包，忽略 `plan/` 中的其他遗留项。
- `~exec`: 用户指定了方案包就用指定的；否则扫描 `helloagents/<branch-name>/plan/`，只有一个时直接执行，有多个时列出清单并等待用户选择。
- 改动授权下自建的轻量方案包: 直接使用。

完整性: `why.md`、`how.md`、`task.md` 齐全且非空；或 `task.md` 顶部带轻量方案包标记 `模式: 轻量迭代`，且“轻量方案包元数据”包含范围摘要、核心场景、知识库同步、ADR 和验证策略。找不到方案包或方案包不完整时，按 `output-format` 的错误格式说明缺什么并停止，不猜测缺失内容。

确定后记为 `CURRENT_PACKAGE`（见 `lifecycle`）。

## 2. 读取方案包

- 完整方案包: `why.md` 确认需求、范围、核心场景和风险；`how.md` 确认技术方案、ADR 和接口/数据/依赖边界；`task.md` 确认任务、依赖顺序和验证命令。
- 轻量方案包: 只读 `task.md` 及其元数据，不要求 `why.md` / `how.md`。

## 3. 按任务清单执行

- 严格按 `task.md` 逐项执行，状态符号见 `lifecycle`；每完成一项立即更新为 `[√]`。
- 跳过 `[-]`: 前置任务失败、条件不满足或已被其他任务覆盖。
- 失败 `[X]`: 记录原因，只继续不依赖失败项且不会扩大损害的任务。失败使成功标准、核心验证、安全或必要知识同步无法满足时停止归档，按 `develop` 的验证失败规则处理；`~auto` 不得把失败任务当作成功归档。
- 标注为 `HITL` 的任务在执行前取得其要求的确认、凭据或环境。
- 迁移前为所有非 `[√]` 任务补充 `> 备注: [原因]`。

## 4. QA 证据

验证完成后读取 `qa-review`，在方案包目录写入 `qa-review.json`。P0/P1/P2 分级和归档门禁以 `qa-review` 为准；门禁未通过时不得进入后续环节，任何命令都不能绕过。

## 5. 解析唯一归档目标

QA 门禁通过后，按 `lifecycle` 的 no-clobber 规则计算 `RESOLVED_ARCHIVE_PATH`。之后知识库链接、history 索引、迁移和最终输出都使用这个值，不再手工拼接路径。

## 6. 同步知识库与 CHANGELOG

- 按 `kb` 的同步规则更新受影响文档；必须在迁移前完成对方案包内容的读取。
- `CHANGELOG.md` 只记录发布相关变化；需要定位版本文件时读取 `templates` 的版本规则。

## 7. 一致性核对

- 本次修改、测试和文档覆盖了方案包的成功标准。
- 本次触达的 API、数据模型和稳定约定在文档与代码之间一致，没有新增死链。
- 不一致时以代码为准修正文档；只有当文档内容来自本次刚确认的方案、而代码存在明显错误时才修正代码。

## 8. 多模型验收（仅用户要求时）

用户明确要求外部验收时读取 `multi_model`，在迁移前执行只读验收，发现项按 `qa-review` 的门禁处理并写入 `qa-review.json`。外部模型全部失败时降级为主代理本地复核，不得记为外部验收通过。未要求时不询问。

## 9. 迁移方案包

存在方案包时不可跳过:

1. 确认 `task.md` 状态和备注反映实际执行结果。
2. 按 `lifecycle` 把方案包从 `plan/` 移动到 `RESOLVED_ARCHIVE_PATH`；移动前复核目标不存在，被占用时重算并先修正已写入的链接。禁止覆盖或合并既有归档，移动失败时保留源目录且不得报告成功。
3. 更新 `helloagents/<branch-name>/history/index.md`。

## 10. 收尾

- 按 `lifecycle` 清理流程状态并扫描遗留方案包。
- 按 `output-format` 的命令完成格式输出，内容包括任务完成统计、验证结果、变更文件、归档路径和剩余风险。存在未闭环的 P0/P1 时不得到达本环节。
