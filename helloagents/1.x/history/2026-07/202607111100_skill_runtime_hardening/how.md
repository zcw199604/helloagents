# 技术设计: Skill 运行时闭环加固

## 技术方案

### 核心技术

- Markdown Skill 契约与 Python 标准库审计器。
- `unittest` fixture 测试与 GitHub Actions Windows/Linux 矩阵。
- Skill 内自包含 bridge 脚本及仓库到安装目录的哈希同步工具。

### 实现要点

1. 在 lifecycle 定义唯一状态集合、等待态和 `RESET_WORKFLOW_STATE` 终态动作；所有命令入口记录本轮授权来源。
2. 给轻量 `task.md` 增加范围、核心场景、知识库同步和验证策略元数据；下游显式分支读取。
3. 多模型验收移动到归档前；P0 回到修复/QA，P1 需明确决策，P2 可记录后继续。
4. 归档目标冲突时使用 `_v2/_v3`，任何移动失败均保留 plan 源目录。
5. 安全审计解析 Markdown shell 代码块和 Python AST 中的进程调用；Skill 审计增加依赖 DAG、Markdown 链接和关键语义不变量。
6. bridge 默认有界超时；Gemini 默认 sandbox，Claude read-only 禁止 Bash/Edit/Write；多行参数不再转义为字面量。

## 设计边界

- **范围内:** 规则、审计、分发和测试闭环。
- **范围外:** 外部 CLI 的真实网络兼容性和生产项目安装。
- **模块职责:** Skill 描述行为；脚本验证可机器判定的不变量；安装工具只在显式 `--install` 时写目标。
- **接口契约:** 保留既有命令别名和 JSON bridge 输出字段；新增参数必须向后兼容。
- **数据边界:** 仅处理仓库文本、临时测试目录和显式安装目标。
- **依赖边界:** 只使用 Python 标准库，不新增第三方依赖。
- **大型项目最小改动:** 不重构无关模板，不修改用户全局 Skill，不调用外部模型。

## 架构决策 ADR

### ADR-005: 使用显式状态机替代隐式布尔授权
**上下文:** 多个 `MODE_*` 在不同文件设置和清理，成功路径存在遗漏。
**决策:** 定义授权态、等待态、终态清理和合法转换表；布尔变量只作为兼容字段且必须绑定当前工作流标识。
**理由:** 状态可达性和权限生命周期可被审计。
**替代方案:** 继续补单点清理语句；拒绝原因是容易再次遗漏。
**影响:** routing、develop、lifecycle 和输出交互规则需要同步。
**状态:** 已采纳

### ADR-006: bridge 作为 Skill 自包含资源分发
**上下文:** 相对仓库根的 `scripts/*_bridge.py` 在独立安装后不可用。
**决策:** 每个 collaborating Skill 携带自身 `scripts/bridge.py`，根脚本作为同步源并由审计校验哈希。
**理由:** 符合 Skill bundled resources 模型，运行路径稳定。
**替代方案:** 依赖环境变量定位仓库根；拒绝原因是安装和调用不自包含。
**影响:** 产生受自动同步保护的镜像文件。
**状态:** 已采纳

## 安全与性能

- **安全:** 外发前数据分类、最小上下文、secret/PII 扫描和授权；审查默认 sandbox/read-only；归档禁止覆盖。
- **性能:** 审计维持标准库实现；安装检查使用 SHA-256；外部 CLI 使用有界默认超时。

## 测试与部署

- **测试:** `python -m unittest discover -s tests -v`、两个审计脚本、bridge compile/help、双树 diff、安装检查 fixture。
- **部署:** 本轮只更新仓库；用户全局安装由新增工具显式执行，本轮不自动写入。
