# 变更提案: Skill 运行时闭环加固

## 需求背景

并行审查确认当前 Skill 在静态结构审计通过的情况下，仍存在授权状态泄漏、轻量方案包下游不兼容、历史归档覆盖、多模型只读与数据出境门禁不足、bridge 分发失效以及审计假阴性等问题。

## 变更内容

1. 将分散布尔状态收敛为显式交互状态和统一终态清理规则。
2. 统一完整与轻量方案包在 develop、QA、KB 和 lifecycle 中的契约。
3. 将归档改为禁止覆盖，并补充多模型 P0 阻断、安全沙箱和数据出境门禁。
4. 让 bridge 随 Skill 自包含分发，并提供安装副本检查/同步能力。
5. 扩展审计脚本、单元测试和跨平台 CI，覆盖语义不变量。

## 范围边界

- **范围内:** Codex/Claude 中文 Skill 树、bridge 与审计脚本、测试、CI、当前分支知识库。
- **范围外:** 真实调用外部模型、修改用户全局安装目录、发布远程仓库或修改第三方 CLI。
- **拆分说明:** 按状态机、方案包、安全协作、分发、验证五个闭环实施，最终统一复审。

## 影响范围

- **模块:** routing、develop、lifecycle、kb、qa-review、multi_model、collaborating-*、output-format、templates。
- **文件:** 两端 Skill/Reference、`scripts/*.py`、`tests/*`、CI、知识库。
- **API:** 审计脚本增加可选安装目录检查；bridge 增加有界超时并收紧 sandbox 默认值。
- **数据:** 不修改业务数据；方案包迁移必须 no-clobber。

## 核心场景

### 需求: 授权与交互状态闭环
**模块:** routing/lifecycle/develop

#### 场景: 命令完成后处理新请求
任一成功、失败、取消或终止路径结束后：
- 所有命令授权和等待交互状态均被清理。
- 下一请求不能继承旧 `MODE_*` 权限。

### 需求: 轻量方案包可完整执行
**模块:** routing/develop/qa-review/kb

#### 场景: task-only 方案包恢复执行
- develop、QA 和 KB 从轻量元数据读取范围、场景和同步要求。
- 安全检查、验证和 QA 证据不因轻量模式跳过。

### 需求: 外部协作和归档安全
**模块:** multi_model/lifecycle/collaborating-*

#### 场景: 多模型只读审查与历史迁移
- 外发前完成敏感数据审查和用户授权判断。
- 审查进程默认只读且有超时；P0 阻止归档和成功总结。
- history 同名目标不被覆盖。

### 需求: 审计可证明关键不变量
**模块:** scripts/tests/CI

#### 场景: 引入危险命令或状态机回归
- Markdown shell fenced block和 Python subprocess 中的危险命令会使安全审计失败。
- 依赖环、状态未清理、轻量契约断裂和安装副本漂移会被自动测试发现。

## 风险评估

- **风险:** 规则改动跨多个 Skill，容易产生新的交叉引用不一致。
- **缓解:** Codex 侧单点修改后机械同步 Claude 镜像；用 fixture 测试、双树哈希和子代理复审收口。
- **风险:** bridge 安全默认值可能改变既有调用行为。
- **缓解:** 保留显式放宽选项，默认 deny-by-default，并只做本地帮助/单元测试，不调用外部服务。
