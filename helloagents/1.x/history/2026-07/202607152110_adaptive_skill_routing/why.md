# 变更提案: 自适应 Skill 路由与 Eval 基线

## 需求背景

当前 HelloAGENTS 已具备完整的阶段流、静态审计和安全门禁，但普通 Bug 与低风险小改动仍被强制导向方案包和多轮确认，且缺少可执行的行为评测用例。需要在保留高风险门禁的前提下，为用户已明确授权的低风险改动恢复连续实施能力，并用 eval 数据集防止后续回退。

## 变更内容

1. 建立机器可校验的 Skill 路由 eval 用例集、结果评分脚本和单元测试。
2. 精简 Codex/Claude bootstrap，只保留稳定原则、最小路由、命令入口和 Skill 索引。
3. 将普通 Bug 和小改动从文件数量路由调整为风险与不确定性路由。
4. 保留 EHRB、生产操作、不可逆变更、公共契约和需求歧义的方案与确认门禁。

## 范围边界

- **范围内:** Codex/Claude 中文 bootstrap、routing/develop 规则、eval 数据与脚本、审计测试、知识库和变更记录。
- **范围外:** 真实调用外部模型、修改用户全局安装副本、移除现有命令、重构其他 Skill、修复既有 Gemini bridge 镜像漂移。
- **拆分说明:** 三项需求共同修改路由契约和审计基线，作为一个可验证闭环实施。

## 影响范围

- **模块:** bootstrap、routing、develop、eval、audit、knowledge-base。
- **文件:** `Codex/Skills/CN/AGENTS.md`、`Claude/Skills/CN/CLAUDE.md`、双端 routing/develop 规则、`evals/*`、`scripts/*`、`tests/*`、知识库。
- **API:** 新增本地 `scripts/eval_skills.py` 命令行接口；不改变外部 API。
- **数据:** 新增静态 JSON eval 数据；无业务数据迁移。

## 核心场景

### 需求: Skill 行为评测基线
**模块:** eval/audit

#### 场景: 校验代表性任务的预期路由
给定咨询、普通 Bug、小改动、架构变更和 EHRB 提示词：
- eval 数据必须声明预期路由、执行动作、确认策略和过程产物等级。
- 校验脚本必须拒绝缺失字段、重复 ID、覆盖不足和无效枚举。
- 提供实际结果时必须输出可复核的准确率与不必要确认率。

### 需求: 精简 bootstrap
**模块:** bootstrap

#### 场景: 常驻入口只保留稳定约束
- bootstrap 保留语言、安全、真实性、写入授权、最小路由、命令和 Skill 索引。
- 阶段细节、状态枚举、输出模板和方案包算法继续由按需 Skill 承担。
- Codex 与 Claude bootstrap 保持内容一致并显著减少行数。

### 需求: 自适应普通开发路由
**模块:** routing/develop

#### 场景: 用户明确要求修复普通 Bug
- 先复现和定位根因，再补回归测试、最小修复并验证。
- 无 EHRB、无架构/公共契约扩张且需求明确时，不强制创建方案包或二次确认。
- 根因不明、连续失败或范围升级时回到方案设计或请求确认。

#### 场景: 用户明确要求低风险小改动
- 根据可逆性、外部副作用、公共契约、数据迁移和不确定性判定风险。
- 低风险改动直接实施并验证；中风险改动允许先形成内部简短计划后连续实施。
- 高风险改动仍须方案包和用户确认。

## 风险评估

- **风险:** 放宽普通开发入口可能被误解为放宽高风险授权。
- **缓解:** eval 覆盖生产、支付、权限、数据迁移和不可逆操作；规则显式排除 EHRB 与公共契约扩张。
- **风险:** 精简 bootstrap 后静态审计依赖的关键文案丢失。
- **缓解:** 同步调整语义审计，改为验证稳定入口和按需 Skill 的契约归属。
- **风险:** eval 只验证结构而不能自动证明模型真实表现。
- **缓解:** 脚本同时支持导入实际结果评分，静态用例作为可接入真实运行器的第一阶段基线。
