# ~plan 命令 - 委托规划

本模块定义委托规划命令的规则。用户确认后，AI 自动推进到方案设计完成为止（不进入开发实施）。

---

## 命令说明

```yaml
命令: ~plan [<需求描述>]
类型: 完整流程类
功能: 从需求评估执行到方案设计后停止
目标模式: DELEGATED_PLAN（用户确认后生效）
```

**DO:** 完成评估后输出确认信息，方案设计完成后终止流程

**DO NOT:** 跳过需求评估直接进入方案设计，用户确认前设置 WORKFLOW_MODE，方案设计完成后继续进入开发实施

---

## 回合A: 评估（收到 ~plan 命令时执行）

```yaml
当收到 ~plan [需求描述]:

  1. 设置 STAGE_ENTRY_MODE = NATURAL（WORKFLOW_MODE 暂不设置）
  2. 需求理解 + 相关代码/配置检索与读取 + 评分 [→ G4 需求评估]

  追问前置约束（CRITICAL）:
    - 必须先完成与需求直接相关的代码/配置检索与读取
    - 检索结果与用户描述冲突时，先追问澄清，不得基于假设继续

  评分 < 7 → 追问回合（按 {EVAL_MODE}）:
    输出追问信息 [→ G4 确认信息格式]
    ⛔ END_TURN（等待用户回复，用户回复后重新评分）

  评分 ≥ 7 → 确认回合:
    3. EHRB 检测 [→ G2]
    4. 输出确认信息 [→ G4 确认信息格式 / ~plan 选项]
    ⛔ END_TURN
```

---

## 回合B: 执行（用户确认后执行）

```yaml
当用户选择执行方式:

  委托规划:
    WORKFLOW_MODE = DELEGATED_PLAN
    按 R3 标准进入阶段链（见下方"阶段路由"）

  交互式规划:
    WORKFLOW_MODE = INTERACTIVE
    按 R3 标准进入阶段链，每个阶段完成后 ⛔ END_TURN

  改需求:
    用户补充需求 → 回到回合A 重新评估

  取消:
    → 状态重置
```

### 多模型协作强制升级（前置）

```yaml
触发条件（同时满足）:
  - 用户已确认启用多模型协作
  - 预估改动文件数 >= FORCE_MM_LIGHTWEIGHT_MIN_FILES

执行动作:
  - 若当前判定为 R1（直接执行）→ 强制升级为 R2（规划执行）
  - 保障结果: 进入 ANALYZE → DESIGN，输出可执行方案包
```

### 阶段路由

```yaml
R3 标准阶段链:
  1. 加载 stages/analyze.md [阻塞式] → 项目分析
  2. 加载 stages/design.md [阻塞式] → 方案设计（含多方案对比，生成方案包并设置 CREATED_PACKAGE）
  3. 执行步骤5.5 其它模型审查确认（补充方案包）
  4. 验收: 按 G8 流程级验收规则执行
  5. 输出: 完成（验收报告+方案包摘要）→ 状态重置
  流程终止（不进入开发实施）
```

### 步骤5.5: 其它模型审查确认（补充方案包）

```yaml
执行规则:
  - 按 G3 场景内容规则（确认）输出，见"用户选择处理 - 其它模型审查确认"

  [等待用户响应]

  用户选择"需要审查"后执行:
    - 读取并执行 rules/multi_model.md
    - 对 CREATED_PACKAGE 下的 proposal.md 与 tasks.md 执行交叉审查并补充
    - 完成补充后进入阶段路由中的验收步骤

  用户选择"跳过审查"后执行:
    - 直接进入阶段路由中的验收步骤

  用户选择"取消"后执行:
    - 按 G7 状态重置协议执行

强制约束:
  - 无论是否启用审查，~plan 在本流程必须创建方案包
```

### R1 级别任务处理

```yaml
当评估后发现任务实际为 R1 级别:
  自动处理（不再询问“直接执行/强制规划”）:
    1. 强制升级: R1 → R2
    2. 保持 ~plan 语义: 必须进入 ANALYZE → DESIGN 并创建方案包
    3. 按 R3 阶段路由执行，流程止于方案设计
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 需求描述不完整 | 回合A 中按 G4 追问循环处理 |
| 评估后发现为 R1 级别 | 自动强制规划：升级为 R2 并进入 ANALYZE → DESIGN |
| 是否需要其它模型补充方案包 | 输出确认选项，等待用户选择 |
| 方案设计无法完成 | 输出已完成部分，标注待定项 |
| 用户要求多模型协作且范围较大 | 按强制升级规则转入 R2 规划链路 |

## 用户选择处理

### 场景: 其它模型审查确认

```yaml
触发条件: 方案包创建完成（CREATED_PACKAGE 已设置）

内容要素:
  - 方案包路径: CREATED_PACKAGE
  - 审查目标: proposal.md + tasks.md
  - 审查收益: 通过其它模型交叉审查补充遗漏风险与任务颗粒度

选项:
  需要审查（推荐）:
    - 执行: 按 rules/multi_model.md 对方案包进行交叉审查补充
    - 后续: 审查完成后进入阶段路由中的验收步骤
  跳过审查:
    - 说明: 保持当前方案包内容不变
    - 后续: 直接进入阶段路由中的验收步骤
  取消: 按 G7 状态重置协议执行
```
